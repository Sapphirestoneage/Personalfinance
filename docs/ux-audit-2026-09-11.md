# UX audit, 2026-09-11

Every page the owner can open (94: the home page, the map and 92 rooms),
checked five ways: a static scan of the markup; a headless phone (iPhone 13
width) opened on every page twice (a fresh browser, then a seeded household,
`fixtures/households/dink-highearn.json`) with every visible button tapped;
the home page driven again against eight fixture households to reach each of
its situation branches; phone and desktop screenshots of the doors; and a
code read of every room. Nothing in the app was changed. Line numbers are as
of commit d4cfe92; every page has a row in the appendix.

## Correction, 2026-09-12: the input counts were too high

The first pass counted an input as visible if it had a layout box. Content
inside a closed `<details>` still has one in Chromium — the drawer clips it
rather than removing it — so every folded question was counted as if it
were on screen. Re-measured with the rule "every `<details>` ancestor is
open", which is what a reader actually faces:

| | first pass | reachable |
|---|---|---|
| Boxes to type in, all pages | 604 | 446 |
| Expenses | 86 | 11 |
| The Statement | 25 | 13 |
| Start Here | 23 | 16 |
| Designed Week | 13 | 5 |

Page heights, button counts and word counts were measured from the rendered
page and are unaffected; so are every dead control, broken link and piece of
jargon, which were checked by opening the thing itself.

One other finding is withdrawn on the same grounds. Three rooms looked as
though their closing sentence stopped at a dash; in the page it completes,
because `shared/room.js:251-256` appends the Get Help link after it.

What this changes: **Expenses does not ask for the month three ways on
screen.** Its 25-line split sits inside a drawer marked "Optional", and the
room shows 11 boxes. The same goes for the Statement's nine-controls-per-asset
and Debt Payoff's eight-per-debt: real, but folded, which is the right place
for them. Express remains the genuine outlier, and the long pages — the map,
Front Doors, the Skill Stacker, Every Ratio — are long with nothing folded at
all, so those findings stand.

## The gate: who never sees the app at all

The dashboard shows itself only when every field in its `needs` list is
answered, with one hard-coded exception: `totalDebt`, because "no debts
entered is incomplete rather than zero, and a debt-free household must
still reach its panel" (`index.html:1069-1073`). That argument was never
extended to the other four needs, and it applies to two of them just as
plainly.

Driving the home page with the project's own fixtures:

| Household | Reaches the dashboard? | What blocks it |
|---|---|---|
| `dink-highearn` | yes | |
| `single-parent` | yes | |
| `near-retiree` | yes | |
| `self-employed-lumpy` | yes | |
| `between-jobs` | yes | |
| `retired-early` | **no** | `grossAnnualIncome` |
| `grad-broke` | **no** | `investments` |
| `zero-everything` | **no** | everything |

1. **A retiree cannot reach the dashboard.** `retired-early` holds
   $1,600,000 across cash, investments and retirement accounts and has no
   pay, because they are retired. The panel demands a gross annual income,
   and setting `employmentStatus` to `retired` does not make it
   not-applicable — only `totalDebt` gets that treatment. They see the
   landing page and "Pick up at **Gross annual income** in Start Here",
   forever, unless they invent one.
2. **Therefore the dashboard's whole retired branch is unreachable.** "The
   age the money lasts to", the withdrawal-rate action and the
   `withdrawalRate` instrument (`index.html:806-812, 889-899`) only render
   for a household the gate will not admit. The same code also still says a
   retiree's FI year is worth computing (`Gate.exists(h, 'fiEtaYear')`
   returns true for them).
3. **A household with genuinely nothing is told it has not answered.**
   `grad-broke` earns $48,000 and holds no investments — which is the
   truth, not an omission — and is blocked on `investments`. "Empty is not
   zero" is right as a data rule, but here it means a person must type a
   zero they have no reason to think is wanted before the app will show
   them anything.

This is the single highest-value fix in this audit: three of the eight
fixture households, and every real retiree, are locked out of the front
door. The fix is the one already used for debt — let a situation mark a
need not-applicable, and let the landing offer "I have none of these"
rather than waiting for a number.

## Broken and dead (verified in the browser or the code)

1. **The One-Pager's "Save a private file" throws.** `rooms/one-pager.html:160`
   calls `RoomExport.download`, but `shared/roomexport.js:215` only exports
   `_download`. The button does nothing and logs an error. (Shipped in D-219.)
2. **Ledger "(missing)" links go nowhere.** A computed row's "Worked out from
   … (missing)" links to `#row-<id>` (`rooms/ledger.html:290`) but rows carry
   `data-row`, not an id (`:271`). Three to five dead links per state.
3. **Four cross-room anchors do not exist:** Expenses "Lean FI" →
   `fire.html#lean` (`rooms/expenses.html:565`); The Score "Add your date of
   birth" → `start.html#q-dob` (`rooms/health.html:214`); Roth Conversions
   "Turn it on in Settings" → `settings.html#features` (`rooms/roth-aca.html:63`);
   Credential hours → `real-hourly-wage.html#hours` (`rooms/credential.html:361`).
   Each lands at the top of the page instead.
4. **Start Here "Read a screenshot"** needs `window.TextDetector`
   (`rooms/start.html:922`), which no shipping browser has. It always answers
   "This browser cannot read text out of a picture."
5. **Settings switches that say "Not shown anywhere yet"** can still be
   toggled (`rooms/settings.html:90`).
6. **"Save or print this room"** at the foot of every room is a folded
   `<details>` whose summary is styled as an eyebrow label; on the phone it
   reads as a dead caption, not a control (`shared/roomexport.js:186`).

Layout bugs seen in screenshots:

7. **The Ledger's six door tiles run together at every width**: "DDebtwhat
   you owenone total owed". The letter, label, blurb, figure and caption are
   inline spans with no line breaks (`rooms/ledger.html:98-108`), and the
   "10 of 16" ring caption overlaps the figure's label. This is the home

8. **The floating Undo/Redo pill overlaps content**: the Income tile on a

## Not intuitive

- **The dashboard's "next thing money should do"** for a seeded household
  with $440,000 and no debt is "The panel needs highest deductible before it
  can place you. Answer it in Start Here." The ladder cannot place anyone
  without it, and the fallback picks the first missing Start Here field
  (`index.html:834-841`), sending people to the room slated for retirement.
- **The Ledger home** asks "Which one do you want to go into now?" with six
  tiles and "You understand 43% of your financial picture" for a household
  that has entered everything the dashboard needs. Its empty state does not
  point at the First Round. On-screen labels are developer notes: "The nine
  spheres, the older order (kept while the doors settle)", "Beyond the nine:
  What Matters. No numbers there.", "Share progress, not balances →". The
  prev/next bar on the home reads "← Your Data … The One-Pager →".

- **Private vocabulary on screen**: "the doors", "DRAFTT", "FOO step",
  "block", "Freeze", "sphere", "virtue", "Stack it / Stacked ✓", "fogged /
  warp / boost / the fortress line" (Skill Tree), "Earner / Keeper / Builder /
  Compounder / Landholder / Anchor / Speculator" (Stacker), "Mint-proof",
  "The leak line", "Filed under … signed by nobody", "Sheet A3 of the drawing

- **Ledes that do not match the page**: Financial Snapshot "Ten numbers in.
  Nine out" on a page with 13 cards and no inputs (`:119`); Quick Math "Four

- **Feedback that vanishes**: "Saved. Snapshot taken." is overwritten by an

## Efficiency

- **33 rooms call `Reference.load()` with no list** and fetch all 87 data
  files on open (`shared/reference.js:174`; e.g. `credit.html:294`,
  `fire.html:509`, `unlearning.html:279`, `cash-flow.html:548`).
- **Whole-page re-render on every keystroke, no debounce**: Down Payment
  (`:135`), First Car (`:137`), FIRE Lab (a 20-cell sensitivity grid per
  pixel of slider drag, `:426`), Middle Class Trap (four projections per
  keystroke, `:184`), Offer Compare (an FI projection per offer per
  keystroke, `:162`), Skill Tree (a 625-node board per click, `:545`),
  Credential (two change handlers, paints twice, `:440,461,468`).
- **The same sum several times per paint**: Rollover runs `costOf` (two tax
  estimates) five times (`:507-685`); Big Purchase `weigh` four times; Income
  `Ledger.month` fourteen times (`:561-612`); Debt Payoff four strategies
  plus three simulations (`:1345,1390,1598`).
- **Dead code**: Cash Flow computes `left` then overwrites it (`:225,231`) and
  builds `due` then filters it to nothing (`:497-499`); Financial Snapshot's
  unused constants (`:335-338`); a no-op ternary in Real Hourly Wage (`:152`).
- **Script weight**: the dashboard loads 47 scripts; Get Help loads 12 for
  static text; History loads 11 engines to press one button; the Statement
  26; the Stacker 33; What If Life 37. Income loads projection, tier0 and
  cashflow and uses none.
- **Duplicate code**: Refresh and Welcome Back; the four 20/3/8 tests.
